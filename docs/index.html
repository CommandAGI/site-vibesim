The description format

A VibeSim description is one JSON object. It names the machine, where every joint starts, the point the tool must reach, and what the gripper holds. The bench reads it and runs it.

One example

{
  "machine": "so101",
  "start": {
    "shoulder_pan": 0,
    "shoulder_lift": 0.54,
    "elbow_flex": 0,
    "wrist_flex": 0,
    "wrist_roll": 0,
    "gripper": 1.74
  },
  "goal_mm": [80, -200, 60],
  "payload_g": 0
}

The fields

fieldmeaning
machineThe arm. Today the bench has one: so101, the SO-101, with the joint ranges and servo limits of its published model.
startEvery joint's starting angle, in radians. Each must lie inside that joint's range. Leaving one out is an error, so a scene never guesses.
goal_mmThe point the tool must reach, in millimetres: [x, y, z], the arm's own frame, z up.
payload_gWhat the gripper holds, in grams. The engine adds it to the torque gravity already puts on the chain.

What the run does

  1. Inverse kinematics. Damped least squares finds the chain's angles that put the tool point on the goal, kept inside each joint's range.
  2. Servo step. Each joint is a position servo: torque from the error and speed, capped by the joint's limit, against gravity, the payload, damping and friction. One thousand steps a second, in short substeps for the servo's stiffness.
  3. Settle. The run stops when every joint is within 2 milliradians of its target and every joint has stopped moving, or after six seconds.

What the bench says about a run

Where the tool ended, how long the arm took, and the largest torque any servo used. When a goal is out of reach the bench says so and how far short the tool stopped: it does not pretend the arm got there.

Limits today

One machine, reachable-point goals, no collision with the world and no other physics. The engine is CommandAGI's simulation core, copied into this site (engine/), so a scene and its commands fully determine a run. Tell us the machine you want next: hello@vibesim.pro.
